## 1. このレッスンの目的
リクエストのライフサイクル全体(ユーザーが「送信」を押してから、応答が画面に出るまで)を理解し、アーキテクチャ上の判断とデバッグに役立てる。すべての詳細を暗記する必要はなく、用語と全体の流れに慣れることが目標。

## 2. 5段階のリクエストフロー
1. クライアント → サーバー(リクエスト)
2. サーバー → Anthropic API(リクエスト)
3. モデルの処理
4. Anthropic API → サーバー(応答)
5. サーバー → クライアント(応答、画面に表示)

## 3. サーバーが必要な理由
- クライアントのコードから、直接 Anthropic API にリクエストを送ってはいけない。
- API リクエストには、認証用の秘密の API キーが必要。クライアント内にキーを置くと、誰でも抽出して不正なリクエストができてしまう。
- Web/モバイルアプリは自分のサーバーにリクエストし、サーバーが安全に保管したキーで Anthropic API と通信する。

## 4. API リクエストの作り方
- サーバーは、公式 SDK か、通常の HTTP リクエストで接続する。
- SDK の提供言語: Python、TypeScript、JavaScript、Go、Ruby。
- 必須フィールド(4つ)

| 項目 | 内容 |
|---|---|
| API キー | リクエストの送り主を Anthropic に識別させる |
| モデル | 使うモデルの名前(例: `claude-sonnet-4-5`) |
| メッセージ | ユーザーの入力テキストを含むリスト |
| 最大トークン数 | Claude が生成できるトークン数の上限 |

【補足】SDK では、API キーはクライアント作成時に渡し、`client.messages.create()` の必須の引数は `model`・`max_tokens`・`messages` の3つ(次のレッスン「Making a Request」の内容に関わる。ページ外)。

## 5. Claude の処理の内部(4段階)
| 段階 | 内容 |
|---|---|
| トークン化(tokenization) | 入力テキストをトークン(単語、単語の一部、スペース、記号)に分割する |
| 埋め込み(embedding) | 各トークンを、その単語が持つ可能な意味を表す数値のリストに変換する |
| 文脈化(contextualization) | 周囲の単語に基づいて埋め込みを調整し、文脈上最も可能性の高い意味を決める |
| 生成(generation) | 出力層が、次に来る単語の確率を計算する。確率と制御されたランダム性で単語を選び、シーケンスに追加して、同じ処理を繰り返す |

- 例: 「quantum」は、物理量の離散単位/量子力学の概念/極めて小さいもの/量子コンピューティング、など複数の意味を持ちうる。
- Claude は常に最も確率の高い単語を選ぶわけではない。自然で多様な応答のため。

## 6. 生成を停止する条件
各トークンの後に、次の条件を確認する。
1. 最大トークン数に到達した(指定した上限に達したか)
2. 自然な終了(シーケンス終了トークンを生成したか)
3. 停止シーケンス(あらかじめ定義された停止フレーズに遭遇したか)

## 7. API の応答
- メッセージ: 生成されたテキスト
- 使用量: 入力トークンと出力トークンの数
- 停止理由(stop reason): 生成が終了した理由
- サーバーが応答を受け取り、生成テキストをクライアントへ転送し、画面に表示する。

## 8. 重要なポイント(ページの結び)
- API キーを保護する安全なアーキテクチャを設計できる。
- ユースケースに適したトークン上限を設定できる。
- アプリのロジックで、異なる停止理由を処理できる。
- パイプラインのどこで問題が起きうるかを理解し、デバッグできる。

## 【補足】ページ外の内容(私の整理)
- 以下はページ本文にない。公式ドキュメントでの確認が必要。
- `stop_reason` の値の例: `end_turn`(自然な終了)、`max_tokens`(上限到達)、`stop_sequence`(停止シーケンス)、`tool_use`(ツールの呼び出しを要求)。値の名前は公式ドキュメントで確認すること。
- `max_tokens` で止まった場合、応答は途中で切れている。エージェントループが `stop_reason == "tool_use"` の間だけ続く設計だと、`max_tokens` はループを終えるため、切れた応答が最終結果として扱われる危険がある。
- 試験ガイドとの関係(私の対応づけで、公式の指定ではない): 1.1(エージェントループと `stop_reason`)の土台になる。
