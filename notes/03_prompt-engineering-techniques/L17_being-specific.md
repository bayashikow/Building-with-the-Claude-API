## 1. このレッスンの目的
プロンプトを具体的にする2つの方法(出力品質ガイドラインとプロセスステップ)と、使い分けを理解する。

## 2. 考え方(ページ)
- 結果を改善する最も効果的な方法の一つは、求めているものについて具体的であること。すべてをモデルの解釈に委ねず、求める出力へ導く、明確なガイドラインやステップを提供する。
- 例: 「隠れた才能を発見する登場人物についての短編小説を書いて」だけでは、200語か2,000語か、登場人物は1人か5人か、どんな才能発見のシナリオか、無数の方向に進みうる。具体的なガイドラインで、明確な目標を与えると、出力の**一貫性と品質**が大幅に向上する。

## 3. 2種類のガイドライン(ページ)
| 種類 | 内容 | 制御できること・例 |
|---|---|---|
| 出力品質ガイドライン | 出力が持つべき品質を列挙する | 応答の長さ / 構造とフォーマット / 含める特定の属性や要素 / トーンとスタイル。例: 1,000語未満、才能を明らかにする明確な行動を含む、少なくとも1人の脇役を登場させる |
| プロセスステップ | Claude が従う具体的な手順を与える | 問題を体系的に考えさせたい、最終的な答えの前に複数の視点を検討させたいとき。例: ①ドラマチックな緊張感を生む才能を3つブレインストーミング → ②最も興味深い才能を選ぶ → ③その才能を明らかにする重要な場面の概要を作る → ④インパクトを高める脇役のタイプをブレインストーミング |

- プロの用途では、2つが一緒に使われることがよくある。

## 4. 実世界での影響(ページ)
- 食事計画プロンプトのテストで、ガイドラインを追加すると、評価スコアが **3.92 から 7.86** に上がった(2倍以上)。
- 追加したガイドライン(ページの英語の原文):
  ```
  Guidelines:
  1. Include accurate daily calorie amount
  2. Show protein, fat, and carb amounts
  3. Specify when to eat each meal
  4. Use only foods that fit restrictions
  5. List all portion sizes in grams
  6. Keep budget-friendly if mentioned
  ```
  訳: ①正確な1日のカロリー量を含める ②タンパク質・脂質・炭水化物の量を示す ③各食事の時間を指定する ④制限に合う食品だけを使う ⑤すべての分量をグラム単位で示す ⑥予算に言及があれば、予算に配慮する。

## 5. いつ使うか(ページ)
| 種類 | 使う場面 |
|---|---|
| 出力ガイドライン | **ほぼすべてのプロンプト**に含める。一貫した有用な結果のための安全網 |
| プロセスステップ | 複雑な問題のトラブルシューティング、意思決定のシナリオ、批判的思考を要するタスク、複数の角度から検討させたい状況全般 |
| 両方の組み合わせ | 出力のフォーマットと内容を制御するガイドラインと、応答前に問題を徹底的に考え抜かせるステップの両方を持つ。結果の一貫性と、すべての重要な要因を検討したという確信が得られる |

- プロセスステップの例: 営業チームの業績低下の分析で、市場指標・業界の変化・個人の業績・組織の変化・顧客フィードバックを検討するよう導く。1つの潜在的な原因だけに焦点を当てさせない。

## 質疑(学習中の確認)
範囲: このレッスン(L17)の内容。

### 質問1: 返信文の一貫性を最も高める書き方はどれか
出題: 顧客の問い合わせメールの返信文を作らせるとき、出力の一貫性を最も高める書き方はどれか。
- A: 「顧客に丁寧に返信してください。」
- B: 「顧客への返信文を作成してください。300字以内。謝罪、原因の説明、再発防止策の3点を含める。敬体で書く。」
- C: 「顧客に返信してください。いい感じにお願いします。」
- D: 「顧客への返信文を作成してください。まず、問い合わせの原因を3つ考え、最も可能性の高いものを選び、その原因を踏まえて回答の方針を決めてから、書いてください。」
- YUTAの回答: B(「具体的なガイドラインを伝えている」)
- 評価: 正解。理由も合っている。
  - B が正しい理由: 長さ(300字以内)、含める要素(謝罪・原因の説明・再発防止策)、トーン(敬体)をすべて指定している。ページの出力品質ガイドラインの4観点(長さ・構造・要素・トーン)に当たる。
  - A: 「丁寧に」はトーンの指定だが、長さも内容も決まらない。
  - C: 「いい感じに」は、解釈をモデルに丸投げする書き方。
  - D: プロセスステップの書き方。ただ、この題材は定型の返信文で、ページの基準では、ステップは複雑な問題に使うもの。出力の形(長さ・含める要素)も決めておらず、一貫性は上がらない。
- 補足: B と D は組み合わせられる。ページの結論は「ガイドラインは常に、複雑な問題にはステップを足す」。この題材なら B で十分で、D のステップは過剰と考えられる(私の判断)。

## 【補足】ページ外の内容(私の整理)
- 食事プランの評価スコアは、同じ題材で順に 2.32(L15 のベースライン)→ 3.92(L16: 明確で直接的)→ 7.86(L17: ガイドライン)と上がった(ページの例)。1つずつ変更を足して測る、L15 の「一度に1つの変更」の実例。1回の評価では点がぶれることがある(ex10 で確認)ため、値は目安として読む。
- 出力ガイドラインは、結合テストの合否基準に近い。基準が具体的なほど、合否が判定しやすい。ex10 で作ったコード採点は、ガイドラインのうち機械的に確かめられる項目(形式・構文)の遵守を測る手段にあたる(私の整理)。
- 「謝罪・原因・再発防止策を含む」のような項目も、語の有無などでコード採点できる場合がある。ただし、中身の適切さはモデルグレーダーや人の判断が要る(L13 のトレードオフ)。
- ステップを書くと、出力が長くなる、または処理が増える可能性がある。費用・速度とのトレードオフがありうるが、ページには書かれていない(確かでない)。
