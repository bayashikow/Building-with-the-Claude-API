## 1. このレッスンの目的
Claude が呼び出すツール関数の定義と、書くときの作法(ベストプラクティス)を理解する。最初のツールとして、現在の日時を取得する関数を作る。

## 2. ツール関数とは(ページ)
- リアルタイムの情報へのアクセスや、アクションの実行能力を Claude に与えるための仕組み。
- ツール関数は、Claude が追加の情報が必要だと判断したときに、(自動的に)実行される**普通の Python 関数**。例: 「今何時ですか?」→ 日時ツールで現在時刻を取得する。
- このセクションで実装する3つ: 現在の日付/時刻の取得、日付への期間の追加、リマインダーの設定(L21)。まず最初のものから。
- ページの天気ツール関数の例は、入力を検証し、明確なエラーメッセージを出している。これらは重要なベストプラクティス。

## 3. ベストプラクティス(ページ)
| 作法 | 内容 |
|---|---|
| わかりやすい名前を使う | 関数名とパラメータ名の両方が、目的を明確に示す |
| 入力を検証する | 必須パラメータが空や無効でないことを確認し、そうならエラーを発生させる |
| 意味のあるエラーメッセージを提供する | Claude はエラーメッセージを確認でき、修正した引数で関数呼び出しを再試行する場合がある |

- 検証が特に重要な理由: Claude がエラーから学習するため。「Location cannot be empty」のような明確なエラーなら、適切な場所の値で関数を呼び直そうとする可能性がある。

## 4. 最初のツール関数(ページ)
```python
def get_current_datetime(date_format="%Y-%m-%d %H:%M:%S"):
    if not date_format:
        raise ValueError("date_format cannot be empty")
    return datetime.now().strftime(date_format)
```
- 処理の流れ: ①`date_format` が空なら `ValueError` を発生させる → ②`datetime.now()` で現在時刻を取得する → ③`strftime(...)` で、指定の書式の文字列にして返す。
- `date_format` を引数にする理由: Claude が、異なる形式で時刻をリクエストできるように。
- 呼び出しの例:
  ```python
  get_current_datetime()          # "2024-01-15 14:30:25"
  get_current_datetime("%H:%M")   # "14:30"
  ```
- 空文字の検証が働く可能性は低いが、「入力を検証し、Claude が学習できる有用なエラーメッセージを出す」というパターンを示すための例(ページの記述)。

## 5. 次のステップ(ページ)
関数を作ることは第一歩。次に、その関数を Claude に説明する **JSON スキーマ**を書き、チャットシステムに統合する必要がある。ツール関数のアプローチで、コードを整理され保守しやすい状態に保ちながら、Claude に強力な機能を与えられる。

## 質疑(学習中の確認)
範囲: このレッスン(L22)の内容。

### 質問1: `location` が空のまま呼ばれたとき、どう実装するか
出題: ツール関数で、`location`(場所)が空のまま呼ばれたとき、最も適切な実装は。
- A: エラーにせず、空の値で天気APIを呼び、返ってきた結果をそのまま返す。
- B: 「Location cannot be empty」のように、原因が分かるメッセージで、例外を発生させる。
- C: 空のときは、"Tokyo" などの既定の都市を使って、結果を返す。
- D: 何も返さず(`None`)、処理を終える。
- YUTAの回答: B(「エラーが発生したことを Claude に伝えるため。適切なエラーを返せば Claude が正しい引数で再実行する可能性があるため」)
- 評価: 正解。理由もページの趣旨を押さえている。
  - B が正しい理由: 明確なエラーメッセージを返せば、Claude がそれを読み、場所を補った引数で呼び直せる。エラーは失敗の通知であり、Claude への修正の手がかりでもある。
  - A: 空の値で API を呼ぶと、予期しない結果やエラーが返るおそれがある。何が悪かったかが Claude に伝わらない。
  - C: 既定の都市を勝手に使うと、利用者が頼んでいない場所の結果を、正しい結果のように返す。エラーにならない分、間違いに気づけない(L12 の「静かな失敗」と同じ問題)。
  - D: `None` だけでは、失敗の理由が分からない。Claude は、何を直せばよいか判断できない。
- 補足: 再試行するかどうかは Claude の判断で、保証はない(ページも「再試行する場合がある」と書く)。確実に直す仕組みではなく、直る見込みを高める設計。

### 質問2(YUTAから): このレッスンに実装演習は不要か
- 回答の要点: 関数単体は、API を使わずに動かせて、小さな演習になる。ただ、ツールとして Claude に使わせるには、次のレッスン以降(スキーマ、メッセージブロックの処理、ツール結果の送信)が揃う必要がある。このレッスン単独の演習にするか、L25 までを合わせた演習にするかは、YUTAの判断(下の【補足】参照)。

## 【補足】ページ外の内容(私の整理)
### 初出の文法
- `datetime.now()`: 現在の日時を返す。`from datetime import datetime` が必要(ページは省略)。
- `strftime(書式)`: 日時を、書式付きの文字列にする。`%Y` 年、`%m` 月、`%d` 日、`%H` 時、`%M` 分、`%S` 秒。
- `raise ValueError(...)`: 引数の値が不正なときに出す例外。`except`(受ける側)に対して、こちらは出す側。

### 設計上の読み取り
- 「静かに失敗せず、止めて原因を伝える」(L11 の学び)と同じ設計。ここでは、エラーメッセージの読み手が Claude になる。
- ページは「自動的に実行される」と書くが、L20 で見たとおり、実際に関数を実行するのは自分のアプリ側のコード(Claude が直接実行するわけではない)。実行の仕組みは、後続のレッスンで扱われると思われる(未確認)。
- `datetime.now()` が返すのは、**実行する環境の時計**の時刻。サーバーのタイムゾーン設定に依存する(私の知識)。利用者の地域の時刻とずれる可能性があり、本番では注意が要る。ページでは触れていない。
- 再試行が無限に続かないよう、回数の上限を決める設計が必要になる(ex07 のリトライと同じ考え方)。ページには書かれていない。
